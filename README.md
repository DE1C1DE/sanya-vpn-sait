# Три буквы от Сани

Центральный портал для 3x-ui подписок. Пользователь получает персональный ID без пароля, а v2rayTun — стабильную ссылку вида `https://CENTRAL/sub/TOKEN`. Endpoint подписки отвечает стандартным base64-кодированным списком `vless://` строк, который используется большинством VLESS-клиентов для автоматического обновления.

## Установка одной командой

Поддерживаются Debian и Ubuntu с `apt`, `systemd` и nginx. Нужен доступ root по SSH и открытые порты (для HTTPS — TCP `80` и `443`).

```bash
curl -fsSL https://raw.githubusercontent.com/DE1C1DE/sanya-vpn-sait/main/install-from-github.sh | sudo bash
```

Скрипт автоматически:

- скачает проект из GitHub;
- установит Python, nginx, SQLite, Certbot и системные сертификаты;
- установит приложение в `/opt/tri-bukvy`;
- создаст systemd-сервис `tri-bukvy`;
- создаст `/etc/tri-bukvy.env` с секретами;
- настроит nginx;
- запустит приложение и выведет URL сайта, админки и пароль.

Затем скрипт спросит два значения:

1. **Домен** — если оставить поле пустым и нажать Enter, будет настроен HTTP-режим без сертификата.
2. **Пароль администратора** — если оставить поле пустым, пароль будет сгенерирован автоматически и выведен в конце установки.

Подключить домен и HTTPS на уже установленном сервере:

```bash
sudo bash /opt/tri-bukvy/install.sh --domain vpn.example.com --admin-password 'пароль'
```

Повторный запуск с другим `--domain` переключает сервер на новый домен. Скрипты установки сохраняются на сервере в `/opt/tri-bukvy` (`install.sh`, `backup.sh`).

## Неинтерактивная установка / свой домен

Параметры можно передать заранее — тогда скрипт ничего не спрашивает:

```bash
curl -fsSL https://raw.githubusercontent.com/DE1C1DE/sanya-vpn-sait/main/install-from-github.sh \
  | sudo bash -s -- \
    --domain vpn.example.com \
    --admin-password 'пароль'
```

- `--domain NAME` — домен для HTTPS; без него — HTTP-режим.
- `--admin-password VALUE` — пароль администратора; без него — генерируется.
- `--public-origin URL` — публичный URL, по умолчанию `https://DOMAIN`.
- `--repo OWNER/REPOSITORY` — другой репозиторий (по умолчанию `DE1C1DE/sanya-vpn-sait`).
- `--ref NAME` — ветка или тег (по умолчанию `main`).
- `--force-db` — заменить существующую базу при наличии локальной `data.sqlite3`.

Локальная база `data.sqlite3` переносится автоматически только если на сервере ее еще нет. Перед `--force-db` сделайте резервную копию текущей базы.

## Резервные копии

```bash
sudo bash backup.sh
```

Копии создаются в `/var/backups/tri-bukvy`. Другой каталог можно передать параметром:

```bash
sudo bash backup.sh /mnt/backups/tri-bukvy
```

Кроме того, администратор может скачать JSON-копию пользователей и серверов из админки. JSON предназначен для переноса логической структуры, а `backup.sh` сохраняет полную SQLite-базу вместе с кэшем подписок.

## Обновление приложения

```bash
sudo install -m 0644 app.py /opt/tri-bukvy/app.py
sudo systemctl restart tri-bukvy
sudo systemctl status tri-bukvy --no-pager
curl -fsS https://vpn.example.com/health
```

## Проверка и диагностика

```bash
sudo systemctl status tri-bukvy --no-pager
sudo journalctl -u tri-bukvy -n 100 --no-pager
sudo nginx -t
sudo systemctl status nginx --no-pager
```

Автопродление сертификата выполняет systemd timer Certbot:

```bash
sudo systemctl list-timers | grep certbot
```

## Перенос на новый сервер

1. Выполните `sudo bash backup.sh` на старом сервере.
2. Скопируйте `data-*.sqlite3` на новый сервер как `data.sqlite3` рядом с `install.sh`.
3. Укажите DNS A-запись домена на новый IP.
4. Запустите `install.sh` с тем же доменом.
5. Не используйте `--force-db`, если база уже была скопирована до установки.
6. Проверьте `/health`, вход в админку и одну ссылку `/sub/ID`.

Не переносите `/etc/tri-bukvy.env` в публичный репозиторий: в нем находится пароль администратора.

## Локальный запуск

```bash
VPN_PORTAL_ADMIN_PASSWORD='пароль' python3 app.py
```

Откройте `http://127.0.0.1:8080/admin`. В админке создайте пользователя и добавьте URL его исходной подписки 3x-ui. ID пользователя можно передать пользователю — на его странице будет URL центральной подписки.

## Обновление IP

В админке укажите старый и новый IP. Операция заменяет точное совпадение старого IP только в URL сохраненных источников. Подписки с другими IP не меняются. После следующего запроса клиента портал скачает новый источник и отдаст новые `vless://` строки.

## Важные ограничения

- Исходные ссылки 3x-ui скачиваются при каждом обновлении, поэтому центральный сервер должен иметь исходящий HTTPS-доступ к панелям.
- Пароль администратора задается переменной окружения и не хранится в SQLite.
- Реализован один администратор, как было запрошено.
- Клиентский endpoint отдает только base64-данные со строками `vless://`, без HTML и без служебных сообщений.
- Если клиент не распознает подписку, проверьте, что URL добавлен именно как подписка, а не как одиночная VLESS-ссылка, и что HTTPS-сертификат центрального сервера доверен устройству.
- Без домена используется HTTP: ссылки подписки будут строиться по IP сервера, а HTTPS потребует подключения домена повторным запуском установки.
